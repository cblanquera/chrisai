# Content Repurposing

Turn an existing article, transcript, note, or post into platform-native
writing without producing copy-paste derivatives.

## 1. Read The Source

Identify the source's central argument, supporting evidence, voice, and intended
reader. Preserve exact facts, numbers, quotations, names, and technical terms.

## 2. Extract Standalone Insights

Pull out three to seven insights only when the source supports that many. For
each candidate, identify:

- the claim or lesson
- the example, fact, or story that supports it
- who would find it useful
- whether it can stand alone without the full source

Rank insights by standalone value. Discard derivatives that would be generic
without the missing context.

## 3. Match Insight To Format

- Use a single post for one complete observation, distinction, or data point.
- Use a thread when the value depends on sequence, accumulation, or a narrated
  change in understanding.
- Use a LinkedIn post when the idea benefits from context, reflection, or a
  professional consequence.
- Use an article when several insights form one sustained argument.

Apply `../references/platform-formats.md` only for requested destinations.

## 4. Rewrite Natively

Write each derivative as if it originated on that platform. Change the entry
point, pacing, context, paragraph structure, and closing as needed while
preserving the source meaning.

Do not lead with "I wrote an article about..." when the insight itself can lead.
Do not reuse identical copy across platforms unless the user explicitly wants
a literal cross-post.

## 5. Preserve Voice And Accessibility

Apply `../references/accessible-technical-voice.md` when a derivative assumes
specialized knowledge. Keep the author's personality and reasoning, but give
each derivative enough context to stand on its own.

## 6. Deliver

Organize the response by requested destination. For each derivative, provide:

- the platform and format
- publish-ready copy
- a brief note only when posting order, visual dependency, or source linkage
  materially affects use

Do not add a schedule, calendar, performance forecast, or channel strategy
unless the user explicitly expands the request.
